The **Company** resource lets you pull company records out of Agentova and into your n8n workflows. Whether you need a quick sample of the most recent entries or a complete export of every company in your account, a single node configuration handles both cases. Select `Company` from the **Resource** dropdown, then choose **Get Many** as the operation.

---

## Get Many

The **Get Many** operation sends a `GET` request to `/companies` and returns company records from your Agentova account. By default it returns up to 50 records in a single call, but you can increase that limit or enable automatic pagination to retrieve your entire dataset without building any looping logic yourself.

### Parameters

<ParamField query="returnAll" type="boolean" default="false">
  When set to `true`, the node automatically handles offset-based pagination and fetches **all** company records across as many API requests as needed. Each page requests up to 100 records using the `limit` and `offset` query parameters. The **Limit** field is hidden when this option is enabled, since the node manages page size internally.
</ParamField>

<ParamField query="limit" type="number" default="50">
  The maximum number of company records to return in a single request. Accepts values between `1` and `100`. This parameter is only visible when **Return All** is set to `false`. The value is sent as the `limit` query parameter and also controls the `maxResults` cap for that execution.
</ParamField>

### How Return All works

When you enable **Return All**, the node enters an automatic pagination loop:

<Steps>
  <Step title="First request">
    The node calls `GET /companies?limit=100&offset=0` to fetch the first page of up to 100 records.
  </Step>
  <Step title="Subsequent requests">
    If the API returns a full page (100 records), the node increments the `offset` by 100 and immediately fires the next request — no additional nodes or looping constructs needed.
  </Step>
  <Step title="Completion">
    Pagination stops when a response contains fewer records than the page size, indicating there are no more results. All collected records are then passed to the next node as individual items.
  </Step>
</Steps>

<Note>
  Even with **Return All** enabled, each individual API request fetches a maximum of **100 records** per page. The node handles the iteration automatically, but very large datasets will result in multiple sequential API calls. Keep this in mind if your Agentova account has rate limits.
</Note>

### Choosing the right setting

| Scenario | Recommended setting |
|----------|-------------------|
| Quick preview or sample | **Return All** off, **Limit** set to your desired count |
| Full export or sync | **Return All** on |
| Feeding a fixed number of records to a downstream node | **Return All** off, **Limit** set precisely |
| Building a report across all companies | **Return All** on |

### Example response shape

```json
[
  {
    "id": "cmp_01abc2de3fg4h5i6j7k8l9m0n",
    "name": "Meridian Logistics",
    "industry": "Supply Chain",
    "createdAt": "2023-11-20T09:14:00Z"
  },
  {
    "id": "cmp_02pqr3st4uv5w6x7y8z9a0b1c",
    "name": "Northgate Solutions",
    "industry": "Technology",
    "createdAt": "2024-01-05T16:47:22Z"
  }
]
```

Each company object in the array is emitted as a separate n8n item, so you can process, filter, or forward individual records using standard n8n nodes downstream.

### Using expressions with company data

Reference specific fields from the response in downstream nodes using n8n expressions:

<CodeGroup>
  ```text Company ID
  ={{ $json.id }}
  ```

  ```text Company Name
  ={{ $json.name }}
  ```

  ```text Industry
  ={{ $json.industry }}
  ```
</CodeGroup>
